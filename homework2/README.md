# 练习4：轮廓提取 + 最小外接矩形（定位与尺寸测量）

## 与练习3 的区别

| | 练习3（Canny + Hough） | 练习4（轮廓 + 外接矩形） |
|---|---|---|
| 抽象出来的东西 | 线（一维几何） | 面（二维区域） |
| 中间数据 | 边缘点集 | 二值区域 / 轮廓点列 |
| 输出 | 直线方程、倾斜角 θ | 中心 (x,y)、长宽 (w,h)、θ |
| 能干什么 | 测角、测边距、找边 | 定位、抓取、尺寸测量 |
| 关键函数 | `Canny → HoughLines(P)` | `threshold → findContours → minAreaRect` |

练习 3 只用到边缘点，输出的是线；练习 4 需要把目标当成整块区域，输出的是“这块区域的位置、大小、姿态”。

## 算法

1. 读入原始彩色图
2. 图像过小时等比放大（长边不足 600 时放大到 600，否则轮廓点太少、矩形精度差）
3. 彩色转灰度
4. 高斯平滑 5×5
5. **Otsu 二值化 + 极性自适应**：统计四条边框上白色像素的占比，边框以白色为主说明白色是背景，自动反相，保证“零件 = 白色前景”。（本图零件占 50.3%，用“前景占比 > 50% 就反相”会判错，所以按边框判断）
6. 形态学闭运算补边缘缺口、开运算去噪点
7. **`findContours(RETR_CCOMP)` 轮廓提取**：`hierarchy[i][3] == -1` 是外轮廓，否则是内孔轮廓；取面积最大的外轮廓作为零件本体
8. **`minAreaRect` 最小外接矩形 + `rect.points()`**：得到中心、长宽、旋转角；再取矩形相邻两条边中较长的那条算出“长边方向角”
9. 结果图：外轮廓（黄）+ 内孔轮廓（绿）+ 最小外接矩形（黄，四角点标红）+ 中心十字 + 参数文字

`minAreaRect` 与 `boundingRect` 的区别：后者是水平矩形，零件一倾斜就会框进大量背景；前者是面积最小的旋转矩形，尺寸与角度才真正代表零件位姿。

## 文件

- `contour_rect.cpp`：源程序（OpenCV C++）
- `image.jpg`：原始图片
- `step1_src.png`：原始彩色图
- `step2_resize.png`：等比放大后的处理图（108×48 → 600×267）
- `step3_gray.png`：灰度图
- `step4_blur.png`：高斯平滑
- `step5_binary.png`：Otsu 二值化（前景 = 零件）
- `step6_morph.png`：形态学去噪
- `step7_contours.png`：全部轮廓（外轮廓黄、内孔绿）
- `step8_minrect.png`：最小外接矩形 + 四个角点 + 中心点
- `step9_result.png`：最终结果（轮廓 + 矩形 + 中心十字 + 中心/尺寸/角度/面积/内孔数）
- `hough_version/`：另一版实现（`Canny + HoughLinesP` 检测直线段）的源码与过程图，作为对比参考，不是本练习答案

## 编译运行

```
cl /EHsc /std:c++17 /I "D:\OpenCV\opencv\build\include" contour_rect.cpp ^
   /link /LIBPATH:"D:\OpenCV\opencv\build\x64\vc16\lib" opencv_world4120.lib
contour_rect.exe image.jpg
```

## 结果

| 量 | 值 |
|---|---|
| 轮廓总数 | 4（1 个外轮廓 + 3 个内孔：腰形槽 1 + 圆孔 2） |
| 零件轮廓面积 / 周长 | 96600 px / 1467 px |
| 最小外接矩形中心 | (298, 135) |
| 长 × 宽 | 559 × 181 px |
| 倾斜角 θ | 6.41° |
| 内孔数 | 3 |

> 说明：`image.jpg` 是零件的紧凑裁剪图（108×48），放大 5.56 倍后处理。若换成带传送带背景的原始大图，程序会自动跳过放大步骤，得到的仍是零件的最小外接矩形。
